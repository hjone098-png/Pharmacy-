# خطة العمل: الحفظ الداخلي الدائم لصور الأدوية وخيارات الفرز الثلاثة

يهدف هذا التحديث إلى تلبية طلب المستخدم بدقة وأمان:
1. **الحفظ الداخلي الدائم لصور الأدوية (Internal App Storage)**: تخزين الصور المضافة محلياً داخل مجلد الصور الخاص بالتطبيق (`context.filesDir/medication_images/`) حتى تظل محفوظة بشكل دائم ولا تفقد أبداً عند إغلاق التطبيق أو مسح الذاكرة المؤقتة.
2. **خيارات الفرز الثلاثة**:
   - **وقت إضافة المادة** (حسب التاريخ والوقت الزمني للإضافة).
   - **ترتيب إضافة المادة** (حسب تسلسل المعرف ID أو الترتيب الرقمي للإضافة).
   - **حسب الأحرف الأبجدية** (فرز أبجدي أ-ي لأسماء الأدوية).

---

## 1. التغييرات المعمارية والبرمجية المقترحة

### أ. إنشاء أداة الحفظ الداخلي للصور (`ImageStorageUtil.kt`)
* إنشاء دالة مساعدة تأخذ `Uri` وتنسخ مجرى البيانات (InputStream) إلى ملف محلي دائم داخل مجلد التطبيق الداخلي (`filesDir/medication_images/`).
* تسمية الملف باسم فريد مثل `med_img_${timestamp}.jpg`.
* إرجاع مسار الملف المحلي الدائم وحفظه في حقل `Medication.imageUrl`.

### ب. منطق الفرز في `PharmaOrderViewModel.kt`
* تعريف `enum class MedicationSortOrder`:
  - `TIME_ADDED`: وقت الإضافة (الأحدث أولاً / الأقدم أولاً).
  - `ADDITION_ORDER`: ترتيب الإضافة (تسلسل الإضافة 1، 2، 3...).
  - `ALPHABETICAL`: حسب الأحرف الأبجدية (أ إلى ي).
* إضافة `StateFlow<MedicationSortOrder>` لتمكين الفرز التفاعلي اللحظي لقائمة الأدوية المفلترة دون إعادة تحميل قاعدة البيانات بالكامل.

### ج. تحديث واجهة المستخدم في `OrderCreationScreen.kt`
* إضافة شريط فرز أنيق ومضغوط أعلى شبكة الأدوية (LazyVerticalGrid) يحتوي على شرائح خيارات الفرز:
  - `[🕒 وقت الإضافة]`
  - `[🔢 ترتيب الإضافة]`
  - `[🔤 أبجدياً (أ-ي)]`
* دعم زر تبديل اتجاه الفرز (تصاعدي ⬆ / تنازلي ⬇).
* تحديث نافذة `AddMedicineWithPhotoDialog` بحيث يتم حفظ الصورة مباشرة في الذاكرة الداخلية عبر `ImageStorageUtil` قبل إضافة الدواء لقاعدة البيانات.
